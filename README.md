# DriveLab 智能驾驶工况仿真与辅助分析平台 V1.0

面向车辆测试、底盘及制动转向分析工作的轻量化 Web 辅助平台，把工况参数、简化仿真、采集日志、专业资料和报告整理放在同一个工作台中。主要帮助用户在测试前比较条件、在测试后复盘数据。产品版本 V1.0，计算引擎 1.2.0。

目标用户是相关工程人员和小型研发测试团队。当前已实现最初开发文档中 V1.0 的主要软件流程，属于可运行的平台原型，尚未完成真实车型及企业标定任务验收；教学与课程项目是拓展使用场景。V1.0 按原定范围接收整理后的日志文件，不直接连接或控制车辆硬件。

产品定位、原始需求与实现映射、功能和使用示例见 [软件实现与成果说明书（详细版）](docs/competition/DriveLab-软件实现与成果说明书.docx)。原 [项目说明书（3 页历史简版）](docs/competition/DriveLab-项目说明书.docx) 继续保留，当前实现及边界以详细版和 1.2.0 记录为准。

## 面向谁和解决什么问题

| 目标使用者 | 可完成的任务 |
| --- | --- |
| 车辆测试及底盘分析人员 | 配置工况条件，查看制动、转向及附着需求，比较不同参数方案 |
| 整理采集数据的测试人员 | 导入日志、核对单位和时间，在同一时间轴上查看仿真与采集数据的差异 |
| 小型研发测试团队 | 为各方案保存分析记录，导出包含条件、曲线和依据的报告供交流；当前记录按个人账号隔离 |
| 车辆工程师生等拓展用户 | 用相同流程学习工况、公式、参数变化与数据对标方法 |

例如，用户可比较高速跟驰时降低车速与增加初始间距分别怎样改变停车距离和预测最小间距，再导入对应工况的采集文件查看差异，结合资料与 AI 解释整理报告。平台提供前期分析和复盘支持，具体偏差原因与实车结论仍需结合工程实际判断。

## AI 工况复盘

首页提供工况风险、日志差异、候选方案、资料依据四类任务。先核对当前参数、日志和资料，再执行分析；日志任务缺少日志时不会调用模型。模型可实际读取误差、检索段落、重算自定义候选。候选卡显示修改前后参数和独立计算事实，载入后需要手动运行仿真；重新运行将解除原日志绑定。保存记录会保留任务、原始问题和分析快照，恢复后可继续核对并导出报告。

模型结论中的本次计算事实与一般资料分别呈现。步骤齐全只说明执行产物齐全；数值提及却没有关联计算事实时提示核对。引用编号校验不等于引用语义或真实工程结论已验证。引用纠错提供限长错误定位及真实事实映射，仍最多三次请求，持续失败明确保留规则结果。

## 功能

- 高速跟驰、弯道稳态、动态换道、紧急避障和城市路口；服务端校验参数并重算结果。
- 水平路面恒减速、稳态圆周、运动学单轨和五次换道需求；0.1 s 采样，末段不足 0.1 s 时精确止于用户时间窗。
- 显示和日志均方统计保留原采样网格；约束与计算事实按当前给定方程活动区间的端点、驻点计算连续需求峰值，避障转向限于既定适用速度域。
- 停车距离、全过程间距预测、附着需求、侧向加速度、方向盘角、横摆角速度与估算制动压力；曲线、动画与 CSV 导出。
- CSV/JSON/TXT/TSV 日志清洗、单位换算、排序去重、时间对齐和共同区间插值；四通道 MAE、RMSE、最大绝对误差、平均偏差与覆盖范围。
- PDF/DOCX/TXT/Markdown 知识文件解析，页码/段落锚点与持久化分块索引；BM25 + 512 维词项向量检索。扫描 PDF 不做 OCR。
- 确定性规则分析；免费模型接入后可执行受限工具、依据计算证据与检索段落生成结构化解释。引用无效、请求失败或额度耗尽时明确降级，保留计算结果。
- 流式执行步骤、候选参数独立重算、证据 JSON、输入指纹；过期分析不作为当前记录保存。
- 账户隔离的 D1 记录和知识库；直接下载嵌入中文字体的 PDF，包含参数、图表、误差、来源和执行记录。
- 验证与证据页面：130 项独立解析参考、12 条固定检索回归、4,973 行 comma2k19 公开实测导入样例及来源许可。

## 技术架构

前端使用 React、TypeScript 与 Tailwind CSS，由 Vinext/Vite 提供兼容 App Router 的运行与构建。服务端运行在 Cloudflare Workers，D1 保存按账号隔离的记录及知识索引。

`lib/simulation.ts`、`lib/trajectory-extrema.ts` 和 `lib/logs.ts` 计算工况、连续需求极值与日志误差；`lib/evidence.ts` 登记基线和候选事实。`lib/analysis.ts` 连接词项检索、最多三轮免费模型请求、受限工具与引用校验，失败时返回规则结果。`lib/analysis-snapshot.ts` 在保存、恢复和报告边界检查分析对象结构；`lib/pdf-report.ts` 用 pdf-lib 嵌入中文字体生成报告。页面调用同一组服务端 API，保存和导出时重新核对输入指纹。

典型用途是比较不同车速或车距条件，再用日志、资料与解释核对差异，形成可交流的报告；不能由一次“约束内”判断推导整车安全或实车模型精度。

## 日志协议

```csv
time_s,speed_kmh,yaw_rate_dps,brake_pressure_bar,steering_angle_deg
0,100,0,0,0
0.1,100,0,0,0
0.2,100,0,0,0
```

时间列与至少一个数值通道必需。`timestamp_ms`、`speed_mps`、`yaw_rate_rad` 可自动换算，也可显式指定单位。先将首个有效时间归零，再添加偏移；正偏移使导入曲线向右移动。共同区间外不外推，缺失值不补零。方向盘角不是前轮转角；压力单位 bar。单次最多 5 MB / 20,000 行，通道绝对值不超过 1,000,000，超出时先检查单位。

MAE/RMSE/平均偏差保留共同区间内仿真网格等点权口径；最大误差及峰值时间使用仿真和采集两时间网格的并集，避免漏掉网格间采集尖峰。原始采样数量与插值网格数量分开；超过 1 秒采样间隙会提醒，插值不证明间隙中的真实变化。该提醒阈值是软件政策，不是传感器合格标准。

所有导入日志均按来源未核验处理，文件名不能证明实测、合成或某个公开数据出处。公开 comma2k19 样例不是受控工况；任意参数与其对比的差异不能作为模型精度或传感器故障证据。来源、固定提交、转换方法、哈希和 MIT 许可均随样例保留，可独立核对。

## 工程边界与协作

这是前期需求评估与学习工具，不是完整自动驾驶仿真或车辆安全认证系统。摩擦圆用于需求超限检查，不求解饱和后的真实运动。未包含感知规划、闭环控制、轮胎非线性、悬架、坡度与载荷转移；变速换道中的横摆/转向是近似需求。工程阈值、制动增益和车型适配需要车辆工程成员审核，尚无实车标定精度证据。

换道与避障初始车速低于 5 km/h 时拒绝；该值是本软件适用范围，不是所有车辆的物理或法规限值。1.1.4 已按当前给定方程的实际活动时间区间计算连续侧向、附着及转向需求极值，避障转向只检查最低适用速度以上的区间，低速段仍明确提示未完整评估。该计算不扩展为真实轮胎饱和、碰撞或闭环控制模型。

候选方案使用独立 CAND_n 事实范围，基线不被候选覆盖。保存拒绝结构损坏的分析对象，恢复及 PDF 会隔离损坏分析并保留可用参数和日志，旧文本按未验证内容保留。输入指纹仅检查输入一致性，不是分析完整性或来源真实性签名；引用存在性也不等同自然语言语义正确。

真实模型分析需要联网及合法配置的服务端凭证；材料包不包含令牌，也不要求通过聊天传递密钥。无需模型接入时可完成上述规则演示；已留存的脱敏真实调用记录用于核对对应案例，不能冒充当场联网结果。离线源码与本机演示也不自行替代赛事要求的仓库评审访问。
